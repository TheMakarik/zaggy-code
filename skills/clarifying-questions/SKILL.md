# Уточняющие вопросы для сложных задач

## Когда применять
Задача считается **сложной**, если выполнено хотя бы одно:
- затрагивает несколько слоёв/файлов (Core + Modules + Avalonia) или переписывает существующий компонент с нуля;
- в требовании есть неоднозначности: цвета, размеры, отступы, имена, дефолты, UX, поведение на границах;
- пользователь сказал «не додумывай», «уточни», «посоветуйся»;
- в коде уже есть противоречия (отсутствуют ассеты, дубли, несоответствия).

## Главное правило
**Ничего не додумывать.** Если данных не хватает — спросить. Не изобретать требования, не выбирать цвета/числа/имена «на глаз».

## Процесс
1. **Разведка до вопросов.** Прочитать релевантный код, найти использования, проверить существование файлов/ассетов, опций, ресурсов. Вопросы должны быть предметными, а не общими.
2. **Задать вопросы через инструмент `question`.** Пакетом по 3–5 штук. Для каждого — короткий заголовок и 2–4 варианта.
3. **Всегда предлагать рекомендуемый вариант** первым и помечать `(Рекомендуется)`.
4. **Ждать ответов** до начала большой реализации. Мелкие безопасные шаги можно делать, крупные — только после уточнения.
5. Если по ходу всплыли новые неоднозначности — задать ещё пакет.

## Что обязательно уточнять
- **Цвета.** Точный `#RRGGBB`/`#AARRGGBB`; это ресурс темы (`DynamicResource`) или хардкод; какой теме должен соответствовать; есть ли альфа. Никогда не придумывать цвет самому.
- **Размеры и геометрия.** Толщины, радиусы, отступы, проценты — в DIP или в долях ячейки.
- **Дефолты.** Что показывать/делать, если свойство не задано (`null`).
- **Поведение на границах.** Пустые коллекции, отсутствующие файлы, `null`, превышение лимитов, отмена.
- **Имена.** Файлы, типы, свойства, ключи ресурсов, XML-атрибуты.
- **Архитектура.** Где живёт логика (VM / state machine / сервис), кто владеет данными.
- **Ассеты.** Проверить, что все пути из `IOptions` реально существуют; сообщить о расхождениях и опечатках.

## Как формулировать
- Конкретно и с вариантами, а не «как сделать?».
- Ссылаться на факты из разведки (`file:line`, имя отсутствующего ассета).
- Не давать готовых решений для `//#:NO_AI` файлов — только «что поменять».

## Антипаттерны
- Придумать цвет/размер/имя и молча реализовать.
- Хардкодить цвет там, где должен быть ресурс темы.
- Спрашивать «что делать?» без вариантов и без рекомендованного.
- Начать большую переписку с нуля, не уточнив ключевые решения.
